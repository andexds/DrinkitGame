# DrinkitGame — дизайн-документ прототипа

**Дата:** 2026-05-19
**Тип проекта:** учебный прототип симулятора кофейни
**Платформа:** Telegram Mini App, движок Unity (WebGL build)
**Целевое время прохождения:** ~1 час от старта до открытия всех систем

---

## 1. Видение и скоуп

**Что мы делаем:** Mid-core эконом-симулятор кофейни. Игрок принимает заказы, готовит напитки в мини-игре с элементом скилла, зарабатывает деньги, докупает продукты, открывает новые рецепты, прокачивает кофемашину. Маскот-китёнок **Дринчик** сопровождает игрока эмоциональной реакцией.

**Тон:** дружелюбный, без давления, но с реальной экономикой и прогрессией. Стиль и UX вдохновлены реальной кофейней Drinkit.

**Что НЕ входит в прототип:**
- Реклама, IAP, любая монетизация
- Серверный бэкенд, аналитика, анти-чит
- Социальные TG-фичи (лидерборды, инвайты, подарки)
- Push-уведомления, ивенты, live-ops
- Несколько кофеен / районов / сюжетных глав
- Колд-брю и любые таймер-фермовые механики
- Несколько размеров стаканов (один размер на каждый тип тары)

**Критерий "готовности" прототипа:** игрок может пройти онбординг, выполнить ~60 заказов за час, прокачать машину до T3, открыть все 8 рецептов, покрутить колесо несколько раз — и при этом ни один экран не сломан.

## 2. Игровой цикл

**Core loop (повторяется бесконечно):**

```
Заказ появляется → игрок тапает заказ → готовит в мини-игре →
выдаёт клиенту → получает оплату + чаевые →
[покупает продукты / рецепт / прокачку машины / крутит колесо] →
новый заказ
```

**Мета-цикл (один час игры):**

```
Старт (онбординг) → освоение базы (эспрессо, американо) →
квест T2 → покупка T2 → освоение средних рецептов →
квест T3 → покупка T3 → освоение поздних рецептов →
"всё открыто, играй сколько хочешь"
```

**Goal tracker** (на главном экране сверху) ведёт игрока: текущая цель → что для неё нужно → прогресс.

**Game over отсутствует.** Репутация может упасть до 0.0 — это просто видно, но ни к чему не ведёт.

## 4. Заказы и клиенты

**Спавн:**
- Максимум 3 одновременных заказа.
- Когда есть пустой слот → через рандомные **5–15 сек** появляется новый.
- Все 3 заняты → новых не появляется, пока не освободишь.

**Из чего состоит заказ:**
- Напиток (один из открытых рецептов)
- Модификатор молока (если применимо): коровье/овсяное/кокосовое/миндальное
- Модификатор сиропа (опционально): ваниль/карамель/орех
- Модификатор топпинга (опционально): корица/какао-посыпка/зефирки (зефирки только для какао)
- Тара: "тут" (керамика) или "с собой" (бумажный стакан)

**Веса при генерации:**
- Только что открытые рецепты — приоритет (50% всех заказов в первое время)
- Старые открытые — снижают долю (минимум 10% на самый старый)
- Модификаторы накидываются с шансом ~40% каждый (то есть бывают и "голые" эспрессо без всего)

**Out-of-stock:** Если для рандомно сгенерированного заказа в инвентаре не хватает хотя бы одного ингредиента — этот заказ не создаётся, генератор пытается снова с другими параметрами. Игрок никогда не видит заказ, который не может выполнить.

**Терпение клиента (модель soft-patience):**
- Над заказом — таймер обратного отсчёта от 300 сек (5 минут)
- 0–60 сек прошло (с момента появления): "быстро" → бонус +30% к чеку
- 60–180 сек: "норм" → 0%
- 180–300 сек: "медленно" → −10% к чеку (всё ещё платит)
- 300+ сек: клиент уходит, ничего не платит, **−0.1 репутация**

**Когда игрок вне Telegram:** все таймеры заказов **на паузе**. Возвращается в игру — заказы и таймеры продолжают с того же места.

**Клиенты безликие:** на UI заказа показывается только пузырь с иконками напитка и модификаторов. Аватарок, имён, настроения у клиента нет — это упрощает арт и UX.

## 5. Готовка

Экран готовки — поток шагов под текущий заказ. Каждый шаг — либо **тап** (мгновенно), либо **мини-игра** (с Quality Score). В правом верхнем углу — карточка заказа (что готовим). Слева — пошаговая подсказка (для первых N заказов на каждом рецепте, потом скрывается).

**Общие правила:**
- Игрок может тапнуть **неправильный** ингредиент (например, коровье вместо овсяного) — он попадёт в напиток. Затем при нажатии "Выдать" происходит проверка соответствия заказа.
  - **Если всё совпало** → клиент платит, ингредиенты списываются.
  - **Если нет** → клиент уходит без оплаты, **ингредиенты всё равно списываются**, **−0.1 репутация**.
- Можно отменить готовку через кнопку "Закрыть" — заказ остаётся в слоте, ингредиенты не тратятся, можно вернуться позже.

### 5.1. Поток шагов — эспрессо-семья (эспрессо/американо/капучино/латте/раф)

1. Тапни нужный стакан ("тут" или "с собой")
2. Тапни кофемолку → **M1 "Помол"**
3. Тапни эспрессо-машину → автоматическая экстракция (прогрессбар 1–3 сек в зависимости от тира машины)
4. *(если латте/капучино)* Тапни питчер → тапни нужное молоко → тапни паровик → **M2 "Вспенивание"** → тапни питчер для налива в стакан
5. *(если раф)* Тапни питчер → тапни сливки → тапни паровик → **M2 "Вспенивание"** → налить в стакан
6. *(если американо)* Тапни чайник → налить воду (один тап, без мини-игры)
7. *(если есть сироп)* Тапни нужный сироп
8. *(если есть топпинг)* Тапни нужный топпинг
9. Тапни "Выдать"

### 5.2. Поток шагов — фильтр

1. Тапни нужный стакан
2. Тапни V60-станцию (воронка устанавливается)
3. Тапни кофемолку → **M1 "Помол"**
4. Тапни чайник → **M3 "Проливание"** (long-tap на воронку, удерживай нужное время)
5. Тапни "Выдать"

### 5.3. Поток шагов — матча

1. Тапни нужный стакан
2. Тапни матча-баночку (мерная ложка падает в стакан)
3. Тапни чайник → горячая вода в стакан
4. Тапни венчик → **M4 "Взбивание"** (быстрый rapid-tap 2 сек)
5. *(если с молоком)* Тапни питчер → молоко → паровик → **M2** → налить
6. Тапни "Выдать"

### 5.4. Поток шагов — какао

1. Тапни нужный стакан
2. Тапни какао-баночку
3. Тапни питчер → молоко → паровик → **M2 "Вспенивание"** → налить
4. *(если зефирки)* Тапни зефирки
5. Тапни "Выдать"

### 5.5. Четыре мини-игры

**M1 — Помол (для всех кофе-рецептов):**
- На экране: горизонтальная полоса, по ней быстро движется индикатор слева направо и обратно. В центре полосы — зелёная зона.
- Игрок удерживает палец (long-tap) → запускает помол → отпускает в нужный момент → индикатор останавливается.
- Quality = насколько близко к центру зелёной зоны остановился.
- Ширина зелёной зоны зависит от тира машины: T1 узкая (сложно), T2 средняя, T3 широкая (легко).

**M2 — Вспенивание молока (для всех молочных рецептов):**
- На экране: круглый индикатор "температуры" молока, заполняется по часовой стрелке.
- Игрок удерживает палец → молоко "пенится", индикатор растёт → отпускает в зелёной зоне (60–75% круга = идеально).
- Перегрев (отпустил поздно) → Quality снижен и +небольшая анимация подгоревшего молока.
- Недогрев (отпустил рано) → Quality снижен.
- Тир машины расширяет зелёную зону.

**M3 — Проливание (только для фильтра):**
- На экране: воронка V60, поверх неё — индикатор "сколько лить".
- Игрок удерживает палец на воронке → льётся вода, индикатор растёт.
- Зелёная зона = "нужное количество". Отпустил слишком рано или поздно → Quality ниже.
- Тир машины расширяет зону.

**M4 — Взбивание венчиком (только для матча):**
- На экране: миска матчи, надпись "Тапай быстро!", таймер на 2 сек.
- Игрок делает максимум быстрых тапов за 2 сек.
- Quality = (число тапов / целевое число) × 100, кэп 100.
- Целевое число: 12 тапов за 2 сек (агрессивный, но достижимый темп).

**Quality итоговый по заказу:**
- Среднее всех мини-игр, которые были в рецепте.
- Эспрессо / Американо: только M1.
- Капучино / Латте / Раф: (M1 + M2) / 2.
- Какао: только M2 (нет помола).
- Фильтр: (M1 + M3) / 2.
- Матча без молока: только M4.
- Матча с молоком: (M4 + M2) / 2.

Модификаторы (сироп, топпинг, тара) — это шаги-тапы, они **не влияют на Quality** (не мини-игры).

### 7.2. Экран склада

- Список 15 SKU, у каждого:
  - Иконка
  - Название
  - Текущий остаток
  - Закупочная цена за 1 ед.
  - Кнопки: "+1", "+10", "+50" (50 = с лёгкой скидкой 5%, для удобства)
- Сверху видно текущий баланс.
- Тап на "+N" → проверка баланса → если хватает → деньги списываются, остаток растёт. Если не хватает → кнопка отключается / лёгкое "красное" мигание.

Можно покупать сколько хочешь. Никакой прокачки склада нет.

### 7.4. Открытие SKU в инвентаре

В самом начале игры в инвентаре виден только тот SKU, который имеет хоть какое-то отношение к **открытым** рецептам. Например, пока не открыт раф — сливки не показываются в инвентаре. Пока не открыта матча — матча-порошок не показывается. Сиропы и топпинги открываются вместе с первым рецептом, к которому они применимы (то есть фактически — с самого начала, так как сиропы применимы к любому кофе, и эспрессо открыт сразу).

## 8. Кофемашина и прогрессия

Три уровня. Покупаются один за другим. Каждый требует деньги + квест "продай N штук".

| Уровень | Цена | Квест | Открывает | Эффекты |
|---|---|---|---|---|
| **T1 "Старенькая"** | старт, бесплатно | — | эспрессо, американо | помол: узкая зона; экстракция 3 сек |
| **T2 "Бариста"** | 1 500 ₽ | продай 10 американо | капучино, латте, какао, раф | помол: средняя зона; M2 средняя; экстракция 2 сек |
| **T3 "Профи"** | 5 000 ₽ | продай 5 капучино + 5 латте | фильтр, матча | помол: широкая; M2 широкая; экстракция 1 сек; **+10% ко всем чекам** |

Заметь: **рецепт ≠ возможность**. Чтобы готовить капучино нужно И купить T2, И купить рецепт капучино (за 500 ₽).

Экран "Кофемашина":
- Большое изображение текущей машины (один из трёх спрайтов)
- Список её возможностей
- Если есть следующая — карточка "Следующая машина T2/T3":
  - Цена
  - Прогресс квеста (например, "Продано американо: 7/10")
  - Кнопка "Купить" (активна, только когда выполнены оба условия)

## 9. Колесо удачи

**Жетоны:**
- 1 жетон сразу после онбординга (бесплатное первое вращение)
- 1 жетон каждые 5 выполненных заказов (накопительно)
- На иконке колеса на главном экране — счётчик жетонов

**Колесо: 9 секторов**

| Сектор | Шанс | Приз |
|---|---|---|
| 50 ₽ | 22% | + 50 ₽ |
| 200 ₽ | 18% | + 200 ₽ |
| 500 ₽ | 10% | + 500 ₽ |
| 1 500 ₽ | 3% | джек-пот |
| Молоко ×10 (случайный тип) | 14% | + 10 порций |
| Зерно ×20 | 14% | + 20 шотов |
| Скидка −50% на следующий рецепт | 7% | одноразовый ваучер |
| Бесплатный заказ ×2 чек | 7% | следующий выданный заказ платит x2 |
| "Не повезло" | 5% | ничего, анимация грустного Дринчика |

Сумма = 100%.

**Экран колеса:**
- Большое колесо в центре, можно крутить
- Жетоны: счётчик
- Кнопка "Крутить" (активна если есть жетон)
- После остановки — анимация приза, Дринчик радуется (или грустит на "пусто")
- "Назад" → главный экран

**Ваучер скидки:** если выпал, добавляется в "Активные бусты" (мини-блок где-то на UI). При следующей покупке рецепта в Recipes — автоматически применяется и исчезает.

**Бесплатный ×2 заказ:** активный буст. Помечает следующий завершённый заказ; в момент расчёта итог удваивается. Один раз на буст.

## 10. Экономика

### 10.1. Цены продажи (база, без модификаторов и бонусов)

См. таблицу в разделе 6.1.

### 10.2. Формула финальной выплаты

```
База         = цена_рецепта + сумма_надбавок_модификаторов
Скорость     = "быстро" (<60 сек)   → +30%
               "норм"   (60–180 с)  →   0%
               "медленно"(180–300 с)→ −10%
Качество     = Quality > 80         → +20%
               50–80                →   0%
               < 50                 → −10%
Машина T3    = +10% (если уровень T3)
Чек = База × (1 + Скорость + Качество + Бонус_T3)
```

Минимум: −20% от базы (тормоз + плохое качество). Максимум: +60% (быстро + отлично + T3).

**Когда чек выплачивается:** в момент нажатия "Выдать" если все ингредиенты правильные.
**Если ингредиенты неправильные:** чек = 0, ингредиенты потрачены, −0.1 репутация.

### 10.3. Темп прохождения (прицел)

| Этап | Время | Что доступно |
|---|---|---|
| Онбординг | 0–3 мин | Эспрессо |
| Старт | 3–10 мин | Эспрессо, копится на американо (100 ₽) |
| Накопление + квест T2 | 10–25 мин | Эспрессо + американо, продаём 10 ам. + копим 1500 ₽ |
| Освоение средних | 25–45 мин | Открываются капучино/латте/какао/раф |
| Накопление + квест T3 | 45–55 мин | Копим 5000 ₽ + квест на 5 капучино + 5 латте |
| Финал | 55–60+ мин | T3, открываем фильтр + матчу — "всё доступно" |

Темп прикинут "грязно" — настроим на плейтесте. Главное чтобы порядок цифр был ок.

### 10.4. Балансовая страховка

Если игрок застрял (не хватает денег, нечего делать) — колесо удачи + ваучеры скидки + чаевые от качества дают доп. поток. Это амортизатор для гриндеров.

## 11. Репутация, goal tracker, мета

### 11.1. Репутация

- Хранится как float 0.0–5.0
- Старт: **5.0**
- −0.1 при выдаче неправильного напитка
- −0.1 при уходе клиента (терпение истекло)
- +0.05 если Quality > 90 (медленно растёт обратно)
- Минимум 0.0, максимум 5.0
- **Отображается** на главном экране как звёздочка с числом
- **Не влияет ни на что в прототипе** — игрок может играть с любым числом

### 11.2. Goal tracker (мягкая цель сверху)

Один активный goal в каждый момент. После выполнения переключается на следующий. Логика:

```
Если рецепт американо не куплен  → "Купи рецепт американо (100 ₽)"
Иначе если T2 не куплена          → "Купи кофемашину T2 (1 500 ₽ + 10 ам.)"
Иначе если капучино не куплен    → "Купи рецепт капучино (500 ₽)"
... и т.д. по дереву
Финал                              → "Все рецепты открыты! Просто играй."
```

Goal показывает текущее состояние (например, "Продано американо: 7/10"). При завершении — анимация подсветки + Дринчик радуется.

### 11.3. Мета-стат для отображения

В простом меню "Статистика" (опционально, доступно из паузы или настроек):
- Всего заработано ₽
- Всего напитков сделано
- Лучший Quality за один заказ
- Сколько раз крутил колесо
- Сколько ушло клиентов

Это не геймплейная фича, просто счётчики на будущее.

## 12. Онбординг

Длится ~3 минуты, форсированный, нельзя пропустить (в первой версии прототипа).

**Шаги:**

1. **Сплеш + знакомство (10 сек):**
   - Затемнённый главный экран. Дринчик появляется по центру.
   - Реплика: *"Привет! Я Дринчик. Эта кофейня твоя. Готов?"*
   - Кнопка "Начнём!"

2. **Первый заказ (форсированный):**
   - Главный экран. Стрелка-указатель на левый слот заказа.
   - Слот заполняется заказом "Эспрессо, тут, без модификаторов".
   - Подсказка: *"Тапни по заказу"*

3. **Готовка с пошаговыми хинтами:**
   - Cooking экран. На каждом шаге руки-указатели и подсветки:
     - "Возьми стакан 'тут'" → пользователь тапает керамический стакан
     - "Тапни кофемолку"
     - М1 "Помол" с очень широкой зелёной зоной (на туторе она в 2 раза шире обычной T1) + подсказка
     - "Тапни эспрессо-машину" → авто-экстракция, прогрессбар
     - "Тапни 'Выдать'"

4. **Первая выплата:**
   - Анимация: монеты летят от клиента к балансу. 130 ₽.
   - OrderResult всплывает: "Quality: 95, Скорость: быстро, +130 ₽ + чаевые 39 ₽ = 169 ₽".
   - Дринчик меняется на счастливый: *"Топ! Это твои первые рубли."*

5. **Тур по главному экрану:**
   - Дринчик подсвечивает по очереди:
     - 3 слота заказа: *"Сюда придут заказы — максимум 3"*
     - Кофемашина: *"Это твоя машина — её можно прокачивать"*
     - Колесо: *"А это колесо удачи!"*
     - Склад: *"Здесь покупаешь продукты"*
     - Рецепты: *"Здесь покупаешь новые рецепты — это твой путь развития"*

6. **Бесплатное вращение:**
   - *"Держи бесплатное вращение!"* → переход на экран колеса, форсированный спин, приз падает в карман.
   - Возврат на главный.

7. **Свобода и первый goal:**
   - Дринчик: *"Дальше сам. Накопи 100 ₽ и открой американо — это твоя цель."*
   - Goal tracker сверху подсвечивается: *"🎯 Купи рецепт американо (100 ₽)"*
   - Появляется следующий заказ (уже без подсказок), начинается обычный геймплей.

**Реактивные подсказки (после онбординга, по триггерам):**
- Кончился ингредиент впервые → *"У тебя кончилось [X]. Зайди на склад."*
- Накопился первый жетон колеса → *"Колесо ждёт!"* (мигает иконка)
- Первый раз открылся новый рецепт → Дринчик показывается с поздравлением

После выполнения каждой реактивной подсказки — она больше не повторяется.

## 13. Маскот Дринчик

Китёнок в фирменном стиле Drinkit. Появляется:
- Постоянно — в углу главного экрана (idle)
- В онбординге — по центру с репликами
- В реактивных подсказках — выпрыгивает в углу с пузырём текста
- На экране колеса — рядом, реагирует на результат
- В OrderResult-попапе — реагирует на качество

**Состояния (эмоции) Дринчика:** см. раздел 16 "Список ассетов".

**Поведение:**
- **В обычном геймплее** Дринчик не блокирует UI. Его реплики появляются в маленьком пузыре над/рядом с ним, исчезают через 3 сек или по тапу. Игрок может его игнорировать.
- **В онбординге** Дринчик активно ведёт обучение — затемнение фона, рука-указатель, форсированные клики; всё, что не подсвечено, временно недоступно. После онбординга он "уходит в фон" и появляется только реактивно.

## 14. Save / state

**Подход:** локальный сейв через `PlayerPrefs` Unity, который в WebGL-сборке мапится на IndexedDB браузера (т.е. на Telegram-клиент в кэше). Один ключ = JSON-сериализованное состояние всей игры.

**Что сохраняется:**
- Баланс ₽
- Репутация
- Жетоны колеса
- Текущий тир машины
- Список открытых рецептов
- Текущий goal
- Прогресс квестов (счётчики "продано американо", "продано капучино", "продано латте")
- Остатки всех 15 SKU
- Активные бусты (ваучер скидки, бесплатный ×2)
- Состояние онбординга (пройден/нет, какие реактивные подсказки уже показаны)
- Стат-счётчики (заработано всего, выпито всего и т.п.)
- **Состояние текущих заказов** (что в слотах, на какой секунде терпения) + timestamp последнего сохранения

**Когда сохраняется:**
- После каждого ключевого события: выдача заказа, покупка чего-либо, открытие рецепта, прокачка машины, спин колеса
- При закрытии TG (если есть такой колбэк)

**При загрузке:**
- Если timestamp последнего сохранения был давно — таймеры заказов **остаются на той же секунде**, на которой остановились (модель "пауза при выходе" из вопроса 3). Не "проматываем" таймер.

## 15. Архитектурный скелет Unity

**Целевая версия:** Unity 2022 LTS (или новее), сборка под WebGL.

**Сцена:** одна — `Main.unity`. Все экраны — UI-панели в одном Canvas, переключаются через UIRouter.

**Структура папок проекта:**
```
Assets/
  Art/                  ← все спрайты (placeholder и финальные)
  Data/                 ← ScriptableObject ассеты
    Recipes/
    Products/
    Machines/
    WheelSectors/
    OnboardingSteps/
  Prefabs/              ← UI-префабы (OrderCard, IngredientButton, и т.п.)
  Scenes/
    Main.unity
  Scripts/
    Core/               ← менеджеры
    UI/                 ← UI контроллеры экранов
    Cooking/            ← мини-игры
    Data/               ← ScriptableObject типы
    Save/
    Mascot/
    Telegram/           ← интеграция с TG WebApp
```

### 15.1. ScriptableObject-типы (данные, не код)

- **RecipeDefinition** — id, имя, иконка, стоимость продажи, нужный тир машины, цена покупки рецепта, доп. условие открытия (квест), список нужных ингредиентов (база), список применимых модификаторов, список шагов готовки.
- **ProductDefinition** — id, имя, иконка, закупочная цена, категория, в каких рецептах используется.
- **MachineTier** — id, имя, спрайт, цена покупки, квест-условие, ширина зелёной зоны для M1, ширина для M2, длительность экстракции, бонус к чеку.
- **WheelSector** — id, описание приза, шанс, тип приза (деньги/ингредиент/ваучер), значение.
- **OnboardingStep** — id, описание шага, тип (text/highlight/forced-action), цель подсветки, текст реплики.

### 15.2. Core-менеджеры (MonoBehaviour-синглтоны на одном GameObject "GameRoot")

| Менеджер | Ответственность |
|---|---|
| `GameStateManager` | Хранит всё состояние (баланс, репутация, открытое, квесты), уведомляет подписчиков об изменениях |
| `SaveService` | Сериализация в JSON и в PlayerPrefs, восстановление при загрузке |
| `InventoryService` | Остатки SKU, докупка, расход ингредиентов |
| `EconomyService` | Транзакции: добавить ₽, списать ₽, проверить хватает ли |
| `OrderService` | Спавн заказов, тики терпения, генерация по весам, проверка ингредиентов в наличии |
| `RecipeService` | Каталог рецептов, какие открыты, проверка условий открытия |
| `MachineService` | Текущий тир, прокачка, эффекты тира на мини-игры |
| `ReputationService` | Обновление репутации |
| `GoalTrackerService` | Вычисление текущей цели, прогресса, переключение |
| `WheelService` | Жетоны, рандом по весам, выдача приза |
| `OnboardingService` | Состояние онбординга, какие реактивные подсказки уже показаны |
| `MascotController` | Текущее настроение Дринчика, переключение спрайтов, реплики |
| `UIRouter` | Переключение между панелями |
| `TelegramBridge` | (плейсхолдер) интеграция с Telegram.WebApp JS API: получение user info, init data; на прототипе — просто mock |

### 15.3. Cooking-сабсистема

- `CookingController` — оркестратор сцены готовки. Принимает на вход OrderInstance, последовательно проходит шаги рецепта, активирует нужные UI и мини-игры.
- `MiniGameM1_Grinding` — мини-игра помола.
- `MiniGameM2_Steaming` — мини-игра вспенивания.
- `MiniGameM3_PourOver` — мини-игра проливания.
- `MiniGameM4_Whisking` — мини-игра взбивания.
- Каждая мини-игра — отдельный компонент с публичным API: `Begin()` → `OnComplete(qualityScore)`.

### 15.4. Поток данных

- Все изменения состояния идут через сервисы.
- UI подписан на события сервисов (`GameStateManager.OnBalanceChanged`, `OrderService.OnOrderSpawned` и т.п.) и обновляется реактивно.
- Save срабатывает по подписке на эти же события.

## 17. Что НЕ входит в прототип (anti-scope)

Для ясности, чтобы не "ползло" в скоупе:

- ❌ Любая монетизация (IAP, реклама, премиум-валюта)
- ❌ Серверный бэкенд, аналитика, анти-чит
- ❌ Социальные TG-фичи (друзья, лидерборд, приглашения, обмен подарками)
- ❌ Push-уведомления
- ❌ Несколько кофеен/локаций/районов
- ❌ Сюжет, диалоги клиентов, истории
- ❌ Кастомизация интерьера кофейни (декор, мебель)
- ❌ Колд-брю и любые long-tail таймер-механики (поставил, через час готово)
- ❌ Сезонные ивенты, ежедневные челленджи
- ❌ Прокачка склада (нет лимита)
- ❌ Несколько размеров стаканов (S/M/L) — один размер на каждый тип тары
- ❌ Размер слотов кроме 3 (всегда максимум 3 заказа)
- ❌ Многоязычность (русский только)
- ❌ Анимация полноценная (можно ограничиться 1–3 кадрами и tween-эффектами Unity)

## 18. Открытые вопросы на потом

Эти вопросы НЕ блокируют разработку прототипа, но всплывут при доводке:

- Звуковое оформление (отдельно потом)
- Точные цвета/типографика — берём из Figma-прототипа
- Локализация на английский / другие языки — если когда-нибудь
- Перенос сейва между устройствами (Telegram CloudStorage) — потенциальная фича после прототипа
- Анимации Дринчика (1 кадр vs покадровка) — решаем по мере отрисовки
